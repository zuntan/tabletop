# 実行中の待受ポート変更

2026-10-20。MCPプロセス（stdio接続）は再起動せず、HTTP/WebSocketの待受ポートを変更する。`desk_port_set({port: 4319, confirm: true})`。ポートは1〜65535。

## 手順

接続中の机がある場合、AIが既存の操作を組み合わせる。

1. 最新の机を `desk_save` で保存し、成功を確認する。
2. ポート切替の依頼に基づいて `desk_release` で接続解放する。元のタブは内容を保持したまま残る。
3. `desk_port_set` で待受を変更する。
4. `desk_connection_info` で新ポート・待受・受付状態を確認する。
5. `desk_browser_open` またはURL手動操作で新しい机を開く。
6. 接続後、空の机であることとsession/revisionを確認し、保存済みの机を `desk_load` で復元する。

ブラウザのURLを自動的に書き換えたり、内容を暗黙に移したりはしない。ブラウザの閉じ方はユーザーに任せる。既存のペア情報、接続中の机、未完了の要求・ハンドシェークがある状態では変更を拒否する。切断済みのペア情報が残る場合は、先に復旧するか明示的な手動接続に切り替えるかを決める。

## 動作範囲

- 現在のローカル/LAN公開方針を保持し、同じ方針で新ポートへbindする。LANを勝手に有効化しない。
- 変更先が使用中などでbindに失敗すれば元ポートへ戻す。復旧も失敗した場合は待受不能を報告する。
- 元ポートは新しい接続を受け付けなくなる。変更成功時に既存のHTTP共有URLとハンドオフ券は失効する。
- 同じポートの指定は、待受中なら変更なしとして返す。
- `TABLETOP_PORT`やCodexの起動設定は変更しない。MCP再起動時は設定されたポートに戻る。継続して同じポートを使う場合は起動設定を別途変更する。
- ファイアウォール、ルーター、ngrok等の外部トンネル、OSのネットワーク設定は変更しない。外部到達性は保証しない。
- ブラウザの保存設定（UIテーマ等）はオリジン単位なので、新ポートでは別の記憶領域となる。机ファイルに保存される壁紙やパーツは通常通り復元する。

## 検証

単体で新ポートのHTTP応答・Host/Origin方針・LAN意図の維持・占有ポート時のロールバックを確認。実ブラウザとstdio MCPで保存→解放→変更→新URL接続→復元を確認する。テストはローカルの一時ポートを使用し、実際のLAN公開・OS設定変更はしない。

実機でも4317から4319へ変更し、標準ブラウザで接続・145パーツ復元に成功。MCP再起動後は起動設定の4317へ戻ることを確認済み。
