# 静的ページで机を使う・公開する

静的ページ版は、ブラウザでTabletopの机を開ける版です。AIやMCPを起動する必要がなく、作った机をURLから見てもらう用途にも使えます。

基本の描画・操作・机ファイルの形式は通常版と共通です。見るだけでなく、開いた机を編集して、自分の机ファイルとして持ち帰ることもできます。

## まず机を開く

[チュートリアル机](https://zuntan.github.io/tabletop/?desk=desks/tabletop-guide.tabletop)を開くと、道しるべをたどりながら道具を試せます。

机を指定しない静的ページのURLでは、空の机が開きます。手元の机は「ファイル → アップロード」から読み込めます。

気になるカードを選び、右下の「選択範囲」を押すと、そのカードが見やすい大きさに収まります。基本の編集操作は、[基本操作の説明](./authoring.md)と同じです。

## 編集した机を残す

静的ページ版には、AI接続やサーバー側のSAVE／SAVE AS／LOADはありません。編集結果を残すときは「ファイル → ダウンロード」で .tabletop ファイルを保存します。

公開ページで編集しても、公開元の机は書き換わりません。次に続きを開くときは、自分で保存した机ファイルをアップロードしてください。

PDFやPNGとして取り出すこともできます。ただし、画像やPDFから元の机の編集状態には戻せないため、編集を続けたい場合は机ファイルも保存しておきます。

## URLから特定の机を開く

アプリのURLに desk を付けると、起動時にその机を読み込みます。

```text
https://zuntan.github.io/tabletop/?desk=desks/tabletop-guide.tabletop
```

desk には、アプリの場所から見た相対URLか、HTTP(S)の完全なURLを指定できます。たとえば、同じサイト内の別プロダクトに置いた机も指定できます。

たとえば、机ファイルそのもののURLが次の場合です（例示用のURLです）。

```text
https://example.com/guide.tabletop
```

Tabletopから開くURLは、次のように書けます。desk=の後ろへ、机ファイルのURLをそのまま続けます。

```text
https://zuntan.github.io/tabletop/?desk=https://example.com/guide.tabletop
```

アプリのURLと、読み込む机ファイルのURLを組み合わせる形です。上のexample.comの部分は、実際に机を公開した配信元へ置き換えてください。

参照先のURLに「&」などが含まれる場合は、desk の値全体をURLエンコードしてください。

別ドメインの机を読むには、配信元が外部からの読込を許可している必要があります（CORS）。HTTPSのページからHTTPの机を読むことも、ブラウザに制限される場合があります。

## 最初に見せるカードを決める

机に初期表示カードを登録しておくと、URLで机を開いた直後に、そのカードを選択した「選択範囲」と同じ表示になります。

設定・解除は、通常版でAIに「このカードを初期表示にして」「初期表示を解除して」と依頼し、机ファイルを保存します。「机の見た目」の「初期表示」で登録したIDを確認できます。この欄から直接入力はできません。

別のカードへ案内するURLを作りたいときは、focus にそのカードのIDを指定します。

```text
https://zuntan.github.io/tabletop/?desk=desks/tabletop-guide.tabletop&focus=text-0cc36b55
```

URLのfocusが、机に保存した初期表示より優先されます。どちらも指定しない場合は、机全体を表示します。指定IDが見つからなければ、全体表示に戻して下部に通知します。

初期表示は、起動時にdeskで読み込む机への指定です。通常版のLOADや、静的ページで起動後にアップロード・机リンクから切り替えたときには適用しません。

## 読込後すぐPDFを開く

机を読み込んで、そのままPDFを見せたいときは、pdf=1を付けます。

```text
https://zuntan.github.io/tabletop/?desk=desks/tabletop-guide.tabletop&pdf=1
```

机とMermaidの描画を待ってPDFを作り、同じタブで開きます。机として開き直すには、URLからpdfを外してください。読込や生成に失敗した場合は、机の画面にエラーを表示します。

### URLオプション早見

- **desk**：起動時に読む机のURL。省略時は空の机。
- **focus**：初期表示する対象ID。空なら指定なし。
- **pdf**：空でない値ならPDFを表示。通常は1を使います。0も有効で、無効化の意味にはなりません。

pdfの指定はfocusや机の初期表示より優先されます。focusとpdfは、deskで読み込む机に対して使います。

## 読めない机・つながらない資料があるとき

HTTP 404と表示されたら、机ファイルがそのURLで公開されているか確認してください。GitHubのファイル閲覧ページのURLと、ファイルそのものを取得できるURLは異なります。

机の中の外部画像やWeb資料には、それぞれの配信元への通信が必要です。また、通常版で使っていた自分のPC内の絶対パスは、公開された静的ページからは開けません。机リンクには、公開URLや机からの相対URLを使います。

「AIを起動しなくても使える」ことと、「通信が一切不要」であることは別です。静的ページ版には、オフライン利用のための自動キャッシュはありません。

## 自分のサイトへ公開する

自分の環境で公開する場合は、Tabletopを静的ページ版としてビルドします。ここでは、このリポジトリの構成でGitHub Pagesへ公開する手順を説明します。

```bash
npm ci
npm run build:pages
npm run preview:pages
```

確認用サーバーのURLをブラウザで開きます。標準は http://127.0.0.1:4173/ です。HTMLファイルを直接開く方法は使いません。

公開用の出力はdist-pagesです。通常版のdistとは別で、生成物をGitへコミットする必要はありません。

公開したい .tabletop ファイルをdocs/tabletop/へ置くと、ビルド時にdesks/へコピーされます。配下のディレクトリ構成も保たれます。開発用の机は、このフォルダーへ置かない限りコピーされません。

GitHubのリポジトリ設定で「Pages → Build and deployment → Source」をGitHub Actionsにします。このリポジトリでは、mainへの関連ファイルのpushで公開処理が動きます。Actionsの「Deploy Tabletop Pages」から手動実行することもできます。

机だけを更新するときも、公開元の机ファイルを保存・配置し直してから公開します。公開する机の内容を確認し、公開後は実際のURLから開いて確かめてください。
