# AI用MCP保存・読込

保存成功後、対応ブラウザに保存時点を通知し、同じsessionId・revisionなら未保存状態を解除します。`browserSavedState`がunchanged／unavailableでも、ファイル保存自体の成功は取り消されません。警告を消すための保存再試行はしないでください。[未保存確認](confirmation-dialogs.md)を参照してください。

## 前提

`desk_save` と `desk_load` は、サーバー側のローカルフォルダーに `.tabletop` ファイルを書き込み／読み込みます。エージェント側や人間のブラウザ側のファイルシステムとは限りません。ブラウザUIと同じ [version 1のZIP形式・検証処理](./save-load.md) を使います。旧形式への互換変換はまだありません。

**サーバーとブラウザの両方を新版にする必要があります。** 古い机をいきなり再読込してはいけません。先に旧版の保存ボタンで机を書き出し、サーバー更新・再接続・画面更新の後にUIで復元してください。古いブラウザへの専用要求はエラーになり、勝手に机を移行しません。

## 通常パスの保存・読込

`path`に絶対パス、または保存ルート内のファイル名を指定できます。旧`filename`とは併用しません。日本語名にも対応。`desk_save({path, overwrite:true})`で既存ファイルへ明示的に上書きでき、既定falseでは同名を拒否します。`desk_load`にもpathを渡せます（confirm・expectedSessionId・expectedRevisionは従来どおり必須）。親フォルダーは既存のものを指定し、相対ディレクトリや~展開は使いません。

通常SAVE／LOADの成功通知は、対応ブラウザの通常保存先と最近使った机も更新します。机タイトルやファイル本文は変えません。保存後の追加編集は未保存のままです。保存時の机世代が既に切り替わっていれば古い通知を無視します。[UI・履歴・机リンク](desk-files-and-links.md)。

## 旧filenameによる新規保存

```json
{ "filename": "meeting-2026-10-15-01.tabletop" }
```

上記を `desk_save` へ渡します。応答は `filename`、サーバー上の絶対 `path`、保存時点の `sessionId`／`revision`、`count`、`formatVersion: 1`、`bytes`。机自体、選択、履歴、revisionは変えません。要求で取得した一貫したスナップショットを保存するため、その後の編集は次の保存が必要です。

棚の名前は `settings.name` として保存しますが、ファイル名は従来どおりAIが指定します。人間側の `棚の名前.tabletop` というダウンロード名とは独立し、下記のASCII名制限も変わりません。短い棚IDは保存せず、読込先のIDを維持します。[棚の名前・棚ID・保存名](./desk-identity.md) を参照してください。

- 保存先の既定はサーバー実行ユーザーの `~/.tabletop/saves/`。
- `TABLETOP_SAVE_ROOT` で変更できます。信頼できるローカルディレクトリとその親を指定してください。
- ファイル名だけを指定。先頭は英数字、以後は英数字・ハイフン・アンダースコア、拡張子前は最大80文字、拡張子は小文字 `.tabletop`。パス、区切り、隠し名、Windows予約名を拒否。
- 既存ファイルは上書きしません。別の名前で保存してください。
- 新規ディレクトリはmode 0700、ファイルは0600。WindowsではOSのACLに従います。
- 自動削除や保存ファイルの一覧ツールはありません。容量と保管は利用者が管理します。
- I/O途中で失敗すると未完成ファイルが残ることがあります。同名を上書きせず、状態を確認して別名で保存してください。排他作成の保証が弱いネットワークファイルシステムは対象外です。

## 読込

1. 利用者から、現在の机を置き換える許可を得ます。可能なら先に `desk_save`。
2. `desk_summary` で現在の `sessionId` と `revision` を取得。
3. `desk_load` に次を渡します。

```json
{
  "filename": "meeting-2026-10-15-01.tabletop",
  "confirm": true,
  "expectedSessionId": "現在のsessionId（UUID）",
  "expectedRevision": 12,
  "actor": "senpai"
}
```

`confirm: true`、`expectedSessionId`、`expectedRevision` は必須。`actor` は省略時 `agent-01`。`confirm` は呼出し側の明示確認であり、別の認証や人間向けダイアログではありません。AIは利用者の許可なしにtrueを指定してはいけません。

全体を検証後、ブラウザが確定直前にsessionとrevisionをチェックします。別タブへの再接続や読込中の編集でも、不一致なら置き換えません。破損・不正参照・未知versionも机を変更せず拒否します。正しく読めた場合は一回の共通Undoで戻せます。履歴には指定actorを記録し、選択・指差しを解除、全体表示します。人間が編集中は拒否します。

結果は通常のsummaryに `filename`、`formatVersion`、`missingAssets`（欠落した埋込画像のオブジェクトID）を追加したものです。欠落画像はUIと同じ代替表示になります。古いUndo履歴や接続情報など、ファイルに含めないものもUIと同じです。

## 安全性と上限

- 旧filenameは設定ルート内のみ。path指定はサーバーの絶対パスに対応し、明示依頼された場所だけを操作します。読込は通常ファイルのみで、ファイルのシンボリックリンクは拒否。サイズを制限して読み込み、読み込み途中の変化も確認します。
- ZIPの上限はUIと共通。ただしMCPは既存の24 MB WebSocket上限を守るため、**JSON転送20 MBまで**。埋込画像のbase64も含むため、ZIPが50 MiB未満でも拒否されることがあります。その場合はブラウザの保存・読込を使用してください。
- 保存・検証処理は外部URLを取得しません。読み込んだ後の通常描画は、画像・iframeのURLへブラウザがアクセスすることがあります。
- 保存先の親ディレクトリを別プロセスに差し替えられる環境は保証対象外です。設定ルートは信頼できる専用のローカルフォルダーにしてください。
- 切断・応答タイムアウト時は、読込が適用済みか不明です。自動再送せず、再接続後にsession・revision・内容を確認してください。
- WebSocket切断原因や表示の調査は別件で、ここではheartbeat等を追加していません。

根拠：[Node.js公式fsドキュメント](https://nodejs.org/api/fs.html#file-system-flags) の排他作成 `wx`、ファイルハンドルのstat／readに従っています。`O_NOFOLLOW` はWindowsでは保証されないため、通常ファイル・リンク検査とオープン前後の同一性確認も併用しています。
