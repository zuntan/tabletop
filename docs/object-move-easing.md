# 指差したパーツの移動 easing

2026-10-20。AIが整理するときの「どれがどこへ移ったか」を目で追えるようにする、小さな表示演出。

## 操作と適用条件

1. `desk_point`で対象を示す。
2. `desk_execute`の1バッチで、対象を同じ移動量だけ平行移動する。
3. 350msのease-out（cubic）で到着し、指差しは到着先に残る。

新しいツールや保存プロパティは追加しない。移動要求は`update`の`x/y/x2/y2`だけにする。内容・色・サイズ・追加削除・並べ替えが混在したバッチ、指差し外の直接編集、異なる移動量、端点だけの変形は従来どおり即時反映。指差した全対象が同じ量だけ移動する場合に適用する。内容を書き換えるなら移動前か後の別バッチにする。

クリップを指差して1枚目の座標を動かす場合も、束全体を対象として認める。束・接続された線・ピン・吹き出し先端などの結果座標を同じ進み具合で補間する。設定上のスナップは最終座標にだけ適用し、途中で格子に引っ掛けない。カメラは自動追従させない。

## 状態と割り込み

- 最終座標を先に1回だけ確定。revision・Undo・保存には途中の位置を記録しない。
- 通常のMCP応答は演出終了後。`animation: {status: completed|interrupted, durationMs:350, ids:[...]}`を付ける。対象外・動きを減らす設定・非表示の机では即時反映し、animationは付けない。
- 演出中も読み取りは可能で、机の論理座標は確定済みの最終位置を返す。
- 人間のクリック・ドラッグ・キー・スクロール、別の変更要求、読込・切断・非表示などで演出を終了し、確定済みの位置を即座に表示する。途中の位置を新しい文書状態にはしない。
- 中断は移動の失敗ではない。状態を戻したり、同じ移動を自動再送したりしない。
- 通常の人間のドラッグ・Undo/Redoは即時表示のまま。
- フレーム停止時の期限も設け、MCP要求を待たせ続けない。

汎用アニメーション・パーツ別の時間や移動先・遅延・物理慣性・連続カメラ追従は別の将来案。
