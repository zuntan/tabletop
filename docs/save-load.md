# 保存・読込（format version 1）

## 操作

- ヘッダーの「保存」で、一つの `.tabletop` ファイルをダウンロードします。実体は ZIP32 です。
- 「読込」で `.tabletop` または `.zip` を選択し、置換の確認に同意すると読み込みます。
- 現在の机を残す場合は、先に保存してください。自動保存・サーバーへの保存はありません。
- 読込は全体を検証してから一括反映します。失敗・確認の取消時は現在の机を変更しません。
- 読込後は全体表示し、人間の選択とAIの指差しを解除します。
- 読込も共通履歴の一操作です。「元に戻す」で読込前に戻せます。読込中に机が変更された場合は、上書きせず再試行を案内します。
- 保存ボタンを押した時点の revision を保存します。その後の編集は次の保存に含めてください。

## 保存されるもの／されないもの

保存するもの：オブジェクトID・種類・背面からの順序・位置・寸法・文字・色・リアクション・URL・接続線の端点と接続先・ピン番号と説明・ピン体系・新規作成の既定スタイル。

埋込画像／SVGはバイナリとして同梱し、同じ内容・形式は一つにまとめます。読込時に data URL に復元します。

外部HTTP(S)画像・Web資料・リンクはURLのみ保存します。保存・読込処理はURLの画像を取得しません。ただし読込後の通常の描画では、ブラウザが外部画像やiframeへアクセスします。出所不明のファイルを開く際は注意してください。

保存しないもの：Undo／Redo履歴、sessionId、revision、人間の選択、AIの指差し、ポインタ、カメラ、グリッド吸着ON/OFF、説明文表示ON/OFF、接続トークン、接続情報。読込先タブのモードは維持し、カメラだけ全体表示に変更します。既存タブでは revision は増加し、sessionId は変わりません。

## ZIP構成

- `manifest.json`：`format: "tabletop"`、`version: 1`、`objects`、`settings`、`assets`。
- `objects`：通常のオブジェクト配列。ただし同梱画像の `src` は除きます。
- `assets`：オブジェクトIDから `{ path, mime }` への対応表。
- `assets/<SHA-256>.<png|jpeg|gif|webp|svg>`：画像本体。

同梱画像ファイルだけが欠けている場合は、位置・寸法・タイトルを維持し、`Missing image` の代替画像を表示して件数を通知します。欠落状態で再保存すると代替画像が保存されるため、元画像を含む保存ファイルは別途保管してください。画像の改変・破損、manifestの破損、不正な接続先・ピン体系等は読込全体を失敗させます。

## 制限と安全性

- 圧縮ファイル全体50 MiB、展開合計50 MiB、manifest 16 MiB、画像一枚5 MiB。
- オブジェクト2,000個、ピン体系2,000個、ZIPエントリ2,001個まで。
- パスは `manifest.json` と上記の画像パスのみ許可。重複名・暗号化・分割ZIP・ZIP64・未知のversionは拒否します。
- ZIPのディレクトリ・境界・展開前サイズ制限、展開後サイズ・CRC、画像SHA-256、JSONスキーマとオブジェクト間参照を検証します。
- ZIPはメモリ上だけで処理し、OSのファイルシステムへ展開しません。
- 現版は同期ZIP処理のため、上限付近では一時的に画面が重くなることがあります。
- ZIPの読込はサーバー側のローカル画像インポートと別の経路です。画像内容そのものの安全性を保証するものではありません。

ZIPライブラリは [fflate](https://github.com/101arrowz/fflate)。ZIP生成・展開と展開前フィルタは [公式README](https://github.com/101arrowz/fflate/blob/master/README.md) を参照しています。

## 検証

- `npm exec -- tsx --test tests/desk-file.test.ts`：往復、画像重複排除、欠落画像、原子的置換、Undo／Redo、不正manifest・参照・サイズ。
- `npm exec -- tsx --test tests/desk-file.e2e.ts`：独立したChromeとMCPサーバーで保存・ダウンロード・読込・画像描画・Undo／Redo・破損ファイル・取消を確認。
- 既存の机を開いているタブは、検証のために再読込しません。
