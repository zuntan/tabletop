# ベル待機の小さな実験

2026-10-22。Codex専用の常駐機構にせず、通常のMCPツールとして期限付き待機を提供する。

## 位置づけ

現時点では実験的なおまけ機能。AIから人間へ選択などを依頼した後の期限付き操作待ちと、タブレットを含む机上の短いやり取りを想定する。AIは合意した作業の範囲で「選択してベルを押してください。30秒待ちます」と案内し、取得後に簡易メッセージで応答できる。通常のチャットや常時監視を置き換えず、タイムアウト後は自動で待ち直さない。AI向け手順は `desk_help(topic:"bell-conversation")` で提供する。

## 共通の入口

`desk_bell_wait({afterSequence:0, timeoutMs:1000, epoch?})`

- timeoutMs：0〜60000ms、既定1000。クライアントのツールタイムアウトより短くする
- 初回はafterSequence:0、以後は返されたepochとsequenceを指定
- status：bell／timeout／disconnected／reset。エラーではなく通常の結果
- bell：押印ではなくベル押下。押した時点の選択ID、連番、押下時刻を返す
- 既に新しいベルがあれば即時応答。待っていない間の押下も検出する。複数回は最新に集約
- reset：再起動・接続変更等で世代が変わった。新しいepochとsequenceを基準に、依頼された範囲で待ち直す
- 最大8つの同時待機。接続終了・呼出元のキャンセルでは待機を解放する

待機はサーバーのイベント・タイマーで行い、モデルが1秒ごとに繰り返し呼ぶループは作らない。メイン／サブどちらからも同じツールを利用する。サブエージェントの起動、親への通知、会話終了後の継続、ホストごとのタイムアウトは各エージェント環境に依存する。

## UI

全体表示の隣にベル。AI接続中のみ押せる。選択は呼びかけの対象、ベルは呼びかけそのもの。押すとフッターのベルLEDを点灯する。待機中はベルの枠を強調する。

待機ツール自体はLEDを消さず、次のベル待機以外のTabletop MCPツール呼び出しで点灯表示を消す（ヘルプ等のサーバー内だけのツールも含む）。LEDは通信を受けたことの目安であり、内容を理解・作業完了した保証ではない。公開ビューの読み取りでは確認済みにしない。選択・通知は一時状態で、机の保存データ・revision・Undoには含めない。音は出さない。

## 実験手順

1. 呼出上限を決め、まずメインから1000msの待機を1回呼ぶ
2. 1回だけ、最大10秒の待機中に人間がベルを押す
3. 選択IDと連番を確認し、通常の読み取りでLEDが消えることを確認
4. 必要なら別途、サブエージェントで同じ期限付き待機を試す

無制限の待機・自動再試行は行わない。自動テストのMCPクライアントで成功しても、Codex本体や他製品の実行継続を保証しない。クレジット消費はこの試験だけでは測定しない。

## Codex本体での試験結果（2026-10-22）

- メインから1000msを1回呼出し、約1013msでstatus:timeout
- 続けて10000msを1回呼出し、約10021msでstatus:timeout。その間のベル押下なし
- 予定の2回で終了。実ベル押下による早期復帰・ホストの割り込み・サブエージェント試験は未確認
- 新しいブラウザへ保存済み266パーツを復元し、ベルボタンが有効なことを確認

その後、人間がベル押下済みと連絡。timeoutMs:0、前回の連番0で即時確認し、約11msでstatus:bell・sequence2・選択なしを取得。待機外の押下保持を確認。確認前のLEDは点灯、通常のdesk_summary後に消灯。待機中の押下による早期復帰は引き続き未確認。

追加で最大30秒の待機を1回実施。約12832msで人間のベル押下（連番3、選択なし）によりstatus:bellで早期復帰。CodexメインがMCP待機中にベルを受け取れることを確認。無制限の再待機は行っていない。サブエージェントは未検証。

UI調整：ベルは全体表示と同じ40×46px、隣に24×46pxの［▲］を配置。▲は任意の入力欄を開く。ベルLEDのサイズをAI通信ランプと同じ15×15pxへ変更し、色と点灯方法は維持。

ベルLEDはAI通信ランプと共通の15px・レンズ表現を使用（最終色は黄色、AI側は緑）。ベルLEDは点灯を保持し、AI側の通信ランプは従来どおり点滅する。公開ビューの読み取り、接続維持通信、ベル待機だけでは消灯しない。

ベルは確実な配達・応答の保証ではなく、気づくきっかけとして扱う。消灯はTabletopへのAI通信を観測した目安であり、内容の取得・理解・対応完了ではない。消灯しても保持された連番と通知内容は破棄しない。チャットだけのやり取りや別アプリへのアクセスはTabletopからは検知しない。

## 任意の入力欄

［▲］でのみ入力欄を開く。入力欄はベルを押すための必須条件ではなく、未入力のままベルだけでも使える。確定・Esc・［▲］で閉じても下書きを保持し、ベルを押すと閉じてその時点の文章を通知に添える。Enter／Ctrl+Enter切替と押している間のMarkdownプレビューは既存のテキスト入力と同じ方式。

入力欄はベルの上へ表示し、左上のつまみを左・上へドラッグして拡大する。画面からはみ出さない範囲に制限する。

`desk_bell_wait` が status:bell を返す際、textに押下時の文章を含める。そのとき、押下時から書き換えていない下書きだけを消す。押下後に編集した下書きは保持する。他のツールの通信でLEDが消えても下書きは消さない。

入力はタブ内の一時状態。机ファイルへ保存しない。AIの簡易メッセージは下記のトーストとして表示する。

実機で文章付きベルを確認：text「666」、選択なし、連番1を即時取得。取得後に入力欄が空になり、通常の机確認でLED消灯。

LEDの最終指定：左からベル用、AI用。ベルは黄色（#ffff00）、AI通信は緑。サイズ・レンズ・影は共通。


## AIの簡易メッセージ

`desk_message({text, icon?, durationMs?})` でベルの上へ短い文章を表示する。アイコンは info／success／warning／question／hint（TablerのSVG、MIT）。既定8秒、0なら閉じるまで保持、最大60秒。新しいメッセージで前のものを置き換える。閉じるボタン付き。MarkdownやHTMLは解釈せず、文字列として表示する。

通常は右下のフロート操作欄の左端に揃える。ベル入力欄が開いていれば、その左端に揃えて上へ移動する。入力欄の開閉・リサイズや画面サイズの変更に追従し、フォーカスやカメラを奪わない。画面が狭く全体を配置できない場合は画面内へ収めることを優先する。小さな専用表示を自前で実装し、通知ライブラリは追加しない。机のrevision・Undo・保存形式には影響しない。送信結果はブラウザへの送出を意味し、人間が読んだ保証ではない。
