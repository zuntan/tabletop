# 文章の測定と一枚のテキストカード

## テキストの角丸・余白

`type: text` は既存の背景・輪郭に加え、`cornerRadius` と `padding` で一枚のカードにできます。

- `cornerRadius` は0以上。描画時は幅・高さの半分までに制限。既存フィールドをテキストにも適用します。
- `padding` は上下左右共通、0〜100000の有限値。テキストだけに作用し、省略時は従来どおり6 world units。
- プロパティの「角丸」「内側の余白」から変更。Markdown・左寄せは維持します。
- コピー・Undo・保存読込で保持。寸法・接続アンカーはカード全体の枠です。
- 背景と本文の二つ重ねを解消するための機能です。グループやクリップは、独立した資料同士の意味のあるまとまりに使う、という相談方針です。

古いデータで省略されていたpaddingは6として表示します。cornerRadiusは既存の保存値（通常16）をテキストにも反映するため、以前四角く見えていたテキストの背景も角丸になります。0で四角にできます。新しいpaddingフィールドを含む保存データは、古いアプリの厳密なSchemaでは拒否されます。サーバーとブラウザを揃えて更新してください。保存形式versionは1のままです。

## 読み取り専用の測定

```json
{"tool":"desk_text_measure","arguments":{"ids":["card-a","rect-b"]}}
```

1〜200件の既存IDを指定します。重複はまとめ、不明なIDは全体をエラーにします。LLM向けSchemaに大きなmaxItemsを追加せず、実行時にも件数を制限します。

応答には `sessionId`、`revision`、`coordinateSpace: world`、`fitBoundary: rectangular-frame`、`tolerance: 1`、`measurements` が含まれます。

各結果：

| 項目 | 内容 |
| --- | --- |
| `id` / `frame` | 対象と現在の幅・高さ |
| `status` | `measured`、`pending-fonts`、`unsupported`、`unavailable` |
| `layout` | `markdown` または `plain`（対象外では省略） |
| `overflow.x` / `.y` | 現在の枠に対する横／縦のはみ出し |
| `requiredHeight` | 現在の幅・描画条件で必要な高さ。整数へ切り上げ |
| `canFitByHeight` | 横にはみ出しておらず、高さの調整で収められるか |
| `reason` | 測定できない場合の理由 |

測定に成功した場合だけoverflow・必要高さを返します。画面の「文章の収まりを確認」も同じ関数を使い、対象は選択中のパーツです。測定は文書・選択・指差し・カメラ・履歴を変えず、「ひとりで考える」中も利用できます。

### 測り方と限界

- 対象はテキスト（Markdown）・矩形・角丸矩形。楕円・ピン・メディア等は対象外。
- Markdownは実際に描画した内容を複製し、同じ幅・フォント・行間・パディングで自然な高さをブラウザから取得。測定用DOMは即座に削除します。
- 図形の文字はSVG。明示改行だけで、自動折り返しはしません。同じ文字を等倍のSVGで測定し、ズームによる文字寸法の揺れを避けます。
- 中央配置の上端・下端が収まる必要高さを計算。横はみ出しは高さを増やしても解消しません。
- フォント読込中は待機せず `pending-fonts`。余白で本文の幅がなくなる場合は `unavailable`。値をキャッシュしないため、フォントの完了後は再測定します。
- 外接する四角い枠への収まりを測ります。角丸の隅や輪郭の線幅まで含めた可視輪郭判定、美しさ・読みやすさの判定ではありません。
- 端数の差を許容するため判定には1 world unitの許容差があります。
- MCPの直接読み取り用です。外部GET共有の読み取り機能は今回拡張していません。

## 測定と修正は別

自動リサイズや文章の変更はしません。結果を目安に、枠を広げる・文章を短くする・文字サイズを変える・そのままにする、という判断を人間やAIが行います。
