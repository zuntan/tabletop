### 限定した再現確認

Node.js 24.22.1。時間・ヒープ上限を設けた別プロセスで実施し、開いている利用者の机には試験データを渡していない。時間・ヒープ差は単発測定で、環境やGCによって変わる。

- Tabletopと同じrenderMarkdownで、未閉鎖リンクラベルのASCII本文99,981文字（1カード上限100,000文字以内）を処理。15.0.2で360ms、一時フォルダーだけに置いた15.0.3・同等設定で101ms。50,001文字では122ms対46ms。処理増加を確認したが、タブのクラッシュまでは検証していない。
- 実際のdecodeDeskFileへ不正なobjects配列を持つZIPを渡した。manifest 60,071バイト・30,000個の数値要素に対し、上限3,000件を超えても30,001件のエラーを生成。69ms、ヒープ差約12.7MiB。上限違反を検出した時点では打ち切らないことを確認した。
- 10MBのmanifest上限に収まる不正な配列でも、要素数によって検証用メモリが増える。実際のメモリ枯渇は再現していないため、クラッシュする具体的件数や所要時間は断定しない。

### 公開判断への提案

公開サーバーへ匿名リクエストを送るだけで今回の5件を発火できる経路は確認していない。ただし、MarkdownとZodは悪意ある机ファイルや入力を読み込んだ場合に到達可能。PagesのURL読み込み・配布机の利用もあるため、単にローカル専用だから影響なしとは扱わない。

0.1.0公開前にMarkdownのパッチ更新とZod検証前の入力規模チェックを行い、その他の依存更新とZodのメジャー移行は0.1.1以降へ分ける案を推奨する。全件を次版へ回す選択も可能だが、不正な入力でタブやMCPが応答不能になるリスクを残す判断となる。修正の実装には未着手。
