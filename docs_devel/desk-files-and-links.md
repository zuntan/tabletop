# 通常のSAVE／LOAD・机リンク・最近使った机

## ファイルメニュー

- **SAVE（保存）**：認証済みのMCP接続を通して、サーバー上のファイルへ保存します。初回はパスを入力、以後は同じファイルへ上書き。初回に既存ファイルを指定した場合は上書きを確認します。
- **LOAD（読み込み）**：サーバー上のパスを指定して現在の机を置換します。
- **最近使った机**：保存・読込成功時だけ更新する一覧。選んだ参照を開く、机リンクにする、履歴から外す操作ができます。
- **机リンクを置く**：特定の.tabletopファイルを指すカードを置きます。作成時に相手のファイルを開いたり検証したりはしません。
- **ダウンロード**：ブラウザ単独で現在の机を書き出します。MCP終了後も利用できます。
- **アップロード**：手元の.tabletop／ZIPをブラウザで読み込みます。
- **PDFで開く**：これまでと同じ机全体のPDF出力です。

すべて1段のファイルメニューから選びます。履歴などの選択は共通ダイアログを使い、サブメニューはありません。

## 保存先

パスは**MCPサーバーが動いているPC上**のものです。ブラウザやAIクライアントのPCとは限りません。

- ファイル名だけならTABLETOP_SAVE_ROOT（既定 `~/.tabletop/saves/`）を使います。
- 別の場所は絶対パスで指定。日本語や空白を含められます。拡張子は小文字 `.tabletop`。
- 相対ディレクトリ指定は使いません。`~` の展開もしません。親フォルダーは存在している必要があります。
- 書込みは一時ファイルの完了後に差し替えます。対象のシンボリックリンク・非通常ファイルは拒否します。保存先やその親を他プロセスが変更しない、信頼できるローカルフォルダーを使ってください。
- 机タイトル・保存先パス・ダウンロード名候補は別の値です。タイトル変更で保存先は変わりません。
- 通常SAVE先はタブの実行時情報です。机ファイル本体には入れません。LOAD成功でそのパスを設定。アップロード成功で解除し、アップロードしたファイル名を次回SAVEの候補にします。
- 読込をUndo／Redoした場合は通常SAVE先を解除します。元の机を誤ったパスへ上書きしないため、次のSAVEで改めて指定します。通常の編集のUndoでは解除しません。
- ダウンロードは通常SAVE先を変えず、最近使った机にも追加しません。書出し時点までを保存済み扱いにします。OS側の保存取消や物理書込み完了までは検知できません。

## 机リンク

内部表現は `type: "link"` と `deskPath` の組です。通常のWebリンクとは別にタイトル左側へ机のSVGアイコン、中央に小さな机のSVGイラストを表示し、HTTPの `url` は併用しません。

```json
{"id":"desk-reference","type":"link","text":"別の机","deskPath":"/home/user/desks/project.tabletop","width":360,"height":72}
```

通常クリックは選択、右側の机アイコンで開きます。ダブルクリックすると表示名とパスを編集できます。移動・複製・削除・机保存は通常のリンクカードと同様。AIは既存のdesk_get／desk_executeで取得・変更でき、専用の検索・コピー機能は増やしません。

参照はファイル移動・改名・別PCへ自動追従しません。ファイルがなくてもリンクを残し、開く際は赤字ステータスでI/Oエラーを伝えます。

## 履歴

ブラウザのlocalStorage `tabletop.files.recent.v1` に、解決済みパス・机タイトル・最終利用日時を最大30件保持します。重複パスは先頭へ移動。ファイルの中身や接続資格情報は保存しません。

SAVE／LOAD成功時（AIのdesk_save／desk_load成功通知も含む）だけ更新します。保存先がないアップロード、ダウンロード、失敗した読込は追加しません。削除は履歴の項目だけを外し、ファイルを消しません。ブラウザ／オリジンごとで、同期・移行・パス修復はありません。localStorageが使えない場合はタブ内メモリで継続します。

## 未保存・競合・切断

LOAD・机リンク・履歴・アップロードの置換確認を共通化。未保存時は「保存して切替／保存せず切替／キャンセル」の3択です。「保存して切替」は通常SAVEを使います。保存先入力や上書きの取消、保存失敗、保存中の追加編集があれば切替を中止します。オフラインでは先にダウンロードしてから読み込んでください。

読込ファイル全体を検証し、机の世代とrevisionが変わっていないことを確かめてから置換します。読込中の人間の追加編集は失わず、読込を中止。選択・AI指差し・演出はリセットします。確認やファイル処理中のAI編集は拒否し、後から自動再実行しません。古い机向けの保存通知は新しい机の保存先や未保存状態を変更しません。

認証済みWebSocketでのみファイル要求を扱います。ブラウザ側は30秒で待機を打ち切り、切断・時間切れの操作を自動再送しません。保存結果が不明な場合はサーバー側のファイルを確認してください。MCPの更新は必要ですが、AIが常時応答している必要はありません。

転送JSON20MB・ZIP50MiBなどの上限は既存と同じです。通常SAVE／LOADに入らない大きさの机は、ブラウザ単独のアップロード／ダウンロードを使います。保存形式はversion 1を継続しますが、deskPathを持つ机を古い実装で開くことはできません。
