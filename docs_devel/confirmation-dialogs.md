# 共通の確認ダイアログ

2026-10-23。`src/confirm-dialog.ts`とCSSで、既存の確認を自前UIへ統一。HTMLの`dialog.showModal()`を利用し、ライト／ダークのUI色に追従する。

## 共通操作

- キャンセルを初期フォーカスにする。Enterだけで変更を確定しない。
- Esc、右上の閉じる、キャンセルは同じ中止結果。
- Tab／Shift＋Tabはダイアログ内で循環し、机のショートカットへキーを流さない。
- 閉じた後、元の操作要素が表示中ならフォーカスを戻す。
- 確認を重ねたり後から自動表示したりしない。確認中の追加要求は中止扱い。
- 背後の人間操作を止める。AIの読み取りは継続可能だが、編集・Undo／Redo・選択／指差し・カメラ移動・UIテーマ変更は確認中として拒否する。自動再実行しない。
- 接続が切れたら、開いている確認もキャンセルする。

## 置き換えた処理

| 処理 | 選択肢 |
|---|---|
| ブラウザから机ファイルを読み込む | 未保存なら3択、保存済みなら読み込み／キャンセル |
| 内容を保持して接続先ペアリングを置き換える | 接続を切り替える／キャンセル |
| AI接続を解放して別端末向けQRを出す | 接続を解放する／キャンセル |

接続の許可の意味は変えない。開いただけでは机も接続も変更しない。通常のI/Oエラー通知は既存の赤字ステータスを使う。

## 未保存時の3択

「保存して切り替える」「保存せず切り替える」「キャンセル」。キャンセル優先。

保存して切り替える場合は現在のSAVEを実行してから読込を続ける。保存例外や保存中の追加編集があれば切替中止。読込中もrevisionを確認し、机が変わっていたら置換しない。

**通常SAVEはMCPサーバーへの保存です。** 保存先入力・上書き・履歴・机リンクは[通常のファイル操作](desk-files-and-links.md)を参照。ブラウザ単独の書出しはダウンロードに分けています。ダウンロードは書出し開始を成功基準とする。OSの保存先画面の取消やディスク書込み完了まで検知できるものではない。MCP保存はサーバーI/O成功を基準にする。

## 未保存状態

最後に保存を確認したrevisionと現在のrevisionが異なれば未保存。内容が元へ戻ったかは比較しない。

- 新しい空の机、読込・アップロード成功直後は保存済み。
- 人間・AIの文書編集、Undo／Redoで未保存。選択・指差し・ポインター・パン・ズームでは変わらない。
- UI書出しは開始時のrevisionにだけ保存済みを適用し、途中で編集されていたら適用しない。
- MCP保存は書込み成功後、内部の`file_saved`通知で保存時のsessionId・revisionを照合。一致するときだけ未保存を解除する。
- 保存済み状態はブラウザ内の一時情報。保存形式やUndo履歴に属性を増やさず、文書revisionも増やさない。
- ひとりで考えるモードでも保存完了通知は受け付ける。

`desk_save`の結果には`browserSavedState`（updated／unchanged／unavailable）を追加。保存後の編集ならunchanged、古いブラウザや切断等で通知できなければunavailableの場合がある。ファイル保存自体が成功した場合は成功のまま返す。未保存警告が残っても同じ保存を自動再実行しない。

## 検証

モデルでは古い保存完了通知・別セッション・読込成功／失敗・Undo／Redoを確認。ブラウザでは初期フォーカス、キー循環、取消、AI編集拒否、3択の書出しと読込、保存失敗、MCP保存成功／失敗、既存の接続切替・QR引渡し・復旧を確認する。ライト／ダーク両方を画像確認する。
