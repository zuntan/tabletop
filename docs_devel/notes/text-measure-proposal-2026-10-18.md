# 文章の収まりを測る文具

**後日更新：2026-10-18に実装。現在の仕様は [文章の測定](../text-measure.md) を参照。以下は相談時点の記録。**

## きっかけと目的

机のカード整理で、センパイがブラウザの `clientHeight` と `scrollHeight` を比較して文章のはみ出しを確認した。実際の描画情報を、標準の読み取り能力としてAIへ提供する。

パーツの寸法そのものを測る定規ではなく、「中の文章が収まるか」を知る道具。人間が目で見て判断している情報を、AIにも扱える形にする。

## 初期対象

- テキストパーツ（Markdownを含む）。
- 文字を持つ矩形・角丸矩形。
- 楕円、ピン、画像・SVG・Web・リンクのタイトル等は初期対象から外す案。

## 取得する情報の案

- 縦方向・横方向に現在の枠をはみ出すか。
- 現在の幅で文章全体を表示するために必要な高さ。
- 測定状態。未測定やフォント待ちを成功扱いしない。
- sessionId・revision。測定対象の文書状態を識別する。
- 寸法はズームに左右されない机上の単位。

API名の候補は `desk_text_measure`。対象IDを指定する読み取り専用ツールとし、選択・文書・配置・Undo履歴を変えない。戻り値の具体的なSchemaは実装時に決める。

## 描画に沿った測定

- Markdownは同じ幅・フォント・行間・余白・折り返し条件でブラウザがレイアウトした寸法を利用する。
- 矩形の文字は現在SVG描画で、自動折り返しはなく明示改行のみ。実際の文字描画寸法から枠との関係を測る。
- 横にはみ出す文字列は、高さを増やすだけでは収まらない。その違いを結果に表す。
- 角丸の隅を含めた「収まる」の厳密な定義、端数やフォント読み込みの扱いは実装時に整理する。
- 目安として使う測定値であり、可読性・美しさの判定までは保証しない。

## 測定と修正を分ける

自動的に枠を広げない。枠を広げる、文章を短くする、文字サイズを変える、そのままにする、という判断は人間やAIが行う。修正が必要なら既存の編集操作を使う。

AI専用の自動レイアウトではなく、同じ机を囲むための認識の道具として考える。
