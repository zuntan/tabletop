# 机全体を一ページPDFにする

2026-10-21。ハンコ6種追加より優先。feat/desk-pdfで実装。
ヘッダーの「ファイル ▾」にSAVE（保存）・LOAD（読み込み）・PDFで開くの3項目を一段で表示。
従来の保存・読込処理と確認・Undoを維持し、印刷用の設定画面やページ編集は増やさない。

## PDF

クリック時に別タブを確保してから机全体を生成し、そのタブでapplication/pdfを開く。
印刷・ダウンロードはブラウザ標準PDFビューアを使う。
ポップアップ拒否、読み込み中、外部画像の取得失敗、生成エラーは既存の赤字ステータスで通知。
生成失敗時は確保した空タブを閉じる。元データ・選択・履歴・カメラは変更しない。

描画済みSVGを複製し、カメラ変換を外す。机上の可視パーツを画面外も含めて全て取得し、
その描画範囲の短辺の3%（最低24 world unit）の余白を上下左右に等しく付ける。
2026-10-31、広大な机でもページ端に余裕が見えるよう固定24から変更。
ブラウザとAIのPDF出力で共通。カメラの指定矩形キャプチャは範囲を変えない。非表示設定のピンは表示しない。
空の机は既定の矩形と背景だけを一ページにする。
ピン・リアクションは100%表示時の大きさ、ハンコは通常の中央表示に統一し、ズームと選択状態に依存させない。
背景・グリッドは机の原点を基準に再現。位置・重なり・型抜き・文字・画像・図形を保持。
選択枠・指差し枠・操作ハンドル・別タブの操作ボタンなどは除外。

## 品質と上限

現在は見た目優先のラスタPDF。文字・図形も画像化するため、PDF内のテキスト検索やベクター品質はない。
既存のラスタ化と同じSVG→Canvasの仕組みを共有し、JPEG品質95%で一ページPDFへ埋め込む。
外部ライブラリ・ネットワークのPDF変換サービスは使わない。
原則2px/world unit、一辺8192px・総3200万画素を上限に均等縮小。A4指定やページ分割はしない。
PDFのページは机の縦横比を維持し、通常0.75pt/world unit、長辺14400pt以内へ均等縮小する。
大きな机はその分だけ細部の解像度が下がる。

Web資料のiframeページ本体は取得せず、カード内に代替文を表示し、生成後のステータスにも明記。
HTTP(S)画像はCORSで取得できる場合のみ自己完結化できる。失敗時に黙って画像を落とさず生成エラーにする。
描画中のMermaidや未完了のフォントは、不完全なPDFにせず、完了後に再実行してもらう。

## 確認

一ページの構造、xref、長辺の上限、縦横比、Popplerによる読み取りとPNGレンダリングを確認。
ブラウザで大きく異なるカメラ・選択状態から生成してPDFのバイト一致を確認。
日本語Markdown、画像の型抜き、Mermaid、ピン接続線、ハンコ、背景、画面外の図形を含む試験。
SAVE／LOADを新しいメニュー経由で操作し、既存の内容とUndoを保持することを確認する。

## 検証結果

単体テスト197件、関連ブラウザテスト12件が成功。実机238オブジェクトを一ページPDFにし、Popplerで描画して目視確認。カメラ・選択状態を変えても同一PDFになることを確認。
