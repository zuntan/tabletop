# 接続中の机をまたぐオブジェクトのコピー

## 操作と合意

コピーは従来どおり、タブ内に最後のコピーオブジェクトを保持し、OSのクリップボードには操作ごとの印・外部向けテキストを入れる。コピー時のMCP登録・通信・サーバー保存は行わない。ピンを含む場合は、そのコピーの書式として使用シリーズもタブ内に保持する。

貼り付け時の優先順位は次のとおり。

1. 印が自分のタブで保持するものと一致すれば、従来のタブ内貼り付け。
2. 一致しない有効な印があれば、接続中のMCPへ問い合わせる。MCPは他の接続済みタブへ同じ印を照会する。
3. ちょうど一つのタブから一致するコピーを取得できれば、オブジェクトとして複製する。
4. 未接続・エラー・時間切れ・一致なしなら、従来のテキスト／画像／SVG貼り付けへ進む。

各タブのコピー時刻の比較は行わない。OSのクリップボードにある印が対象コピーを指定する。印のない外部コピーではMCPへ問い合わせない。ユーザーのテキスト入力欄内のコピー・貼り付けはブラウザ標準のまま。

## 貼り付け結果

別机では貼り付け先の表示範囲の中央付近へ、相対位置を維持して配置する。同じ机内では従来どおりグリッド間隔分ずらす。各部品IDと線の接合点IDを新しくし、選択内の接続・吹き出し・ピンの付着・クリップ・クリアファイルの所属を付け替える。コピー対象外への参照は外す。画像／SVGの実データ、Mermaidのソース、ハンコ・リアクション・シール等は部品のデータとして引き継ぐ。

別机のピンは使用シリーズの書式を新しいシリーズとして作り、貼り付け先の同名／同IDシリーズを変更しない。番号は新しいシリーズで採番する。タブ内コピーの番号は従来どおり元シリーズの続きになる。

貼り付けはシリーズ追加も含め一回のUndo対象。元の机・元のコピーは変更しない。別机のコピーを貼っても、貼り付け先がそれ以前に保持していたローカルコピーは置き換えない。

## 実装範囲

AIが呼ぶ新規MCPツールは追加しない。ブラウザの既存認証済み通信を使い、貼り付け先から `file_request` のclipboard_lookupを送り、サーバーが他タブへclipboard_readを中継する。通常SAVE/LOADとは別に処理し、コピーのためにファイルを読まない。

サーバーはコピーをキャッシュしない。元のタブを閉じた・切断した・LOADした・次のコピーで置き換えた場合は取得できない。別サーバーにつながる机や未接続の机とのオブジェクト転送は対象外。同じタブならMCPなしで利用可能。

ベストエフォート：他タブへの照会は並行し各800ms、貼り付け先の応答待ちは1500ms。処理中のタブは取得できない場合がある。自動再試行・再登録・警告ダイアログは増やさない。照会中に貼り付け先の文書が変わった場合は貼り付けを中止し、利用者へ再操作を案内する。

印・部品・シリーズを検証し、他の印や複数の一致応答を採用しない。転送量は既存の20MB上限、部品数・一括操作は既存の200件上限を使う。送信前にもサイズを確認し、大きいコピーで接続を切らない。照会はAIアクセスとしてベルLEDを消さない。

## 検証

- `tests/part-clipboard.test.ts`：印の照合、系列書式の独立、所属／接続IDの付け替え、コピーの不変性、一回のUndo。
- `tests/desk-connections.test.ts`：対象タブ以外への照会、異なる印・複数一致・切断済みの扱い、サーバーに保持しないこと。
- `tests/cross-desk-clipboard.e2e.ts`：コピー後に接続した別タブへの貼り付け、クリアファイル・クリップ束・SVG・ピン、外部テキストと不明な印・元タブ終了時のフォールバック、キー操作の双方向転送、ツールバー貼り付け、接続解放後のタブ内コピー。
- `tests/part-clipboard.e2e.ts`：従来のコピー／カット、連続貼り付け、入力欄の通常操作。

実際の机への反映時は、各机を保存してからMCP・ブラウザを更新する。複数机対応と同じ変更として実装。保存形式の変更はない。

検証結果（2026-10-24）：単体全235件成功、ビルド・型検証成功。関連ブラウザは机間コピー2件・従来コピー2件・複数机1件・クリアファイル2件成功。ベル1件は応答直後のDOM反映待ちを追加して単独再検証。MCP・両タブを更新し、利用者が実際の机間コピーを確認済み。
