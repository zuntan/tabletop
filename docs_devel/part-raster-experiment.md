# カードのラスタ化実験

以下は従来の指差し1枚モードの記録。2026-10-29に同じ`desk_raster`へ`ids`／`bounds`指定の机範囲撮影を追加した。現行の使い分けは[capture-camera.md](capture-camera.md#aiからの画像化2026-10-29)を参照。

BH削除演出の前段階。削除・変形・複数枚の実装はまだ行わない。

1. テキストカード一枚を `desk_point` で指差す。
2. `desk_raster({scale:1})` でブラウザ側がPNGにする。
3. AIはPNG画像と一時ファイルのpath、画像寸法、world bounds、取得時revision、所要時間を受け取る。
4. `desk_asset_import` のsource.pathで同じPNGを通常の画像カードとして隣へ配置する。
   元と等倍で比較するならwidthはbounds.width、heightはbounds.height + 34（画像カードのタイトル）。

SVGの表示ノードを複製し、Markdownの計算済みCSSを埋め込み、SVG画像経由でCanvasへ描画する。
壁紙・選択枠・指差し枠・別オブジェクトの接続線やピンは含まない。
ハンコとリアクションは現在の表示状態。人間が選択中のハンコは縮小表示のまま。
透明背景。システムフォントによる近似であり、完全な画面複製ではない。

scaleは0.1〜3（既定1）、一辺4096px、総800万画素まで。PNG転送も制限する。
時間はブラウザ内のraster（複製・CSS・画像decode・描画）とpng（PNGエンコード）、total。
通信やサーバー書き出し時間は含まない。ズームに依存せずworld寸法を元にするが、
固定画面サイズのリアクションなどは現在の描画形状を使う。

まず一枚の画質と時間を確認する。その後、複数枚一括と、一枚ずつ穴へ入れる方式を比較検討する。

## 最初の実機結果

2026-10-21、`bh-b-sequence` をscale 1で取得。452×340px、49,520 bytes。
ブラウザ内 raster 約19ms、png 約40ms、total 約59ms（単発値）。
`bh-raster-comparison-1x` として元カードの下に等倍配置。文字・枠は確認できた。
画質の最終判断と複数枚の実験はこれから。

## BH比較デモ（削除しない試作）

テキストカード一枚をAI指差しした状態で、メニュー →「BH比較（実験）…」。
同じPNGを使った比較画面を開く。B（落下）は下方移動・入口でのマスク・前後の穴の縁、
A（吸引）は18×12の網目を三角形へ分割し、位置ごとの回転と収縮で変形。
時間軸は共通で前振り300ms、飲み込み850ms、閉じる300ms。合計1500ms。
個別再生・同時再生・最初に戻すが可能。閉じるとアニメーションを停止して表示を破棄する。
机のオブジェクト・履歴・Undoは一切変更しない。Deleteにも結び付けない。
今回の試作はCanvas 2Dの網目変形であり、ピクセルシェーダー方式ではない。
実際の削除への統合、複数枚、演出選択UI、速度などは比較後に検討する。

実際の削除への統合は [BHアニメ削除](bh-delete.md) を参照。比較デモは削除しないまま残す。
