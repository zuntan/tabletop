# HTTP LAN試用

## 公開範囲と制限

- 毎回のプロセス起動は `127.0.0.1` 限定。同じ一つのポートだけを使う。
- 人間が「LANで使えるようにして」等で明示承認した場合に限り、AIが `desk_network_set({ enabled: true, confirm: true })` を呼ぶ。実装・更新・検証だけを理由に開かない。
- 待受は `0.0.0.0`。Host／Originはローカルと現在のプライベートIPv4インターフェース（10/8、172.16/12、192.168/16）のアドレスだけを受け付ける。IPv6、任意のホスト名、インターネット公開は対象外。
- これは送信元IP制限ではない。到達可能なネットワークから接続試行を受けるため、信頼できるLANとOSのファイアウォールを前提とし、ポート転送は設定しない。
- HTTP／wsは暗号化されない。ペアリングを維持しても、盗聴・改ざん・配信コードの差し替えを防げない。秘密情報を扱わない試用向けで、HTTPSの代替ではない。
- MCPは信頼済みAI専用のstdio操作。ブラウザから待受を開くAPIはない。`confirm: true` は利用者の承認を技術的に証明するものではなく、AIが承認を確認する責任を持つ。

## 接続と端末切替

1. LANを開くだけでは、接続中のローカルの机を解放しない。ペアリングと内容を保持する。
2. 別端末へ渡す場合は、人間の了承後に `desk_release({ confirm: true })`。元のタブの自動再接続を止める。
3. `desk_connection_info` の `lanUrls` から接続先を案内する。一つのサーバーに接続できる机は一つ。
4. 新しい接続後は `desk_pairing_info` の秘密recordを直ちに非公開で保持する。

人間は接続タブの「別端末へ渡す」からも切り替えられる。確認後、認証済みWebSocket経由で解放し、元タブの再試行を停止してQRを表示する。LANが未許可なら解放せずエラーにする。LANを開く権限は引き続きAIのみ。

QRは設定済みトークンではなく、サーバーのメモリ上で作る5分・1回限りの秘密URL。新しい机の認証完了、受付の開き直し、LANの無効化、プロセス終了で無効になる。QRを隠す操作は画面から消すだけで、URL自体は期限まで有効。期限切れでも元タブは自動再接続せず、必要なら元タブから手動で戻る。表示は接続パネル内のみで、机の部品・保存ファイルには入らない。HTTPでの盗聴・改ざんリスクは残る。

QR生成は[node-qrcode公式API](https://github.com/soldair/node-qrcode#readme)の `toCanvas` を使い、外部サービスにURLを送信しない。

内容はブラウザにある。接続を変えても保存・コピー・読込・移行は自動実行しない。元の机に内容があり扱いが未指定なら、「机の内容もタブレットへ引き継ぎますか？」と一度確認することを推奨する。空の初期机や明示的な移行／接続だけの依頼では省略できる。これは必須ダイアログではない。忘れた場合は元のタブへ再接続し、AIに移行を依頼する。元タブの内容は残る。

接続タブは伏せ字のURL欄だけ（小さな目アイコンで表示／非表示、×アイコンで欄をクリア。接続自体は切らない）。トークン付きURLを貼り、ページ移動せず接続する。`TABLETOP_TOKEN` 使用時はAIが固定トークンを表示せず、利用者がURLに `#token=` とURLエンコードした値を付ける。トークンなしURLで過去の認証情報を流用しない。URL欄は手動で戻るためタブ内に保持し、共有や画面公開時には秘密として扱う。

`GET /connection-policy` はそのサーバーが現在許可するホストだけを返す（トークンなし、CORSなし、キャッシュ禁止）。取得失敗時はローカル接続だけを許可する。ページのCSPには読み込み時のプライベートIPv4候補を限定列挙するため、インターフェース変更後は保存のうえページを開き直す必要がある場合がある。

## 閉じる・再起動

- `desk_network_set({ enabled: false, confirm: true })` はループバックへ戻し、リモートのソケットを切る。ペアリングやブラウザの内容は消さない。リモート要求が保留中の場合は拒否する。
- 切替失敗時は以前の待受へ復旧を試す。復旧も失敗した場合はLAN許可を閉じ、エラーと `network.listening: false` で停止状態を示す。状態確認後、明示的な操作で復旧する。自動再試行しない。
- 許可されたLAN利用意図は、AIが秘密の継続コンテキストに保持する。サーバーのファイルや環境変数で自動公開はしない。
- MCPアイドル停止等から復帰した場合も最初はローカル限定。AIが有効な承認意図を保持している場合のみ、LAN許可を復元してから正確な `desk_pairing_restore` recordを復元する。ブラウザの再読込や新規ペアリングは使わない。
- 承認が失われた／撤回された場合はLANを復元しない。プロセス停止中に利用可能とは案内しない。

## HTTPブラウザと実装根拠

非セキュアコンテキストでも使えるよう、HMAC-SHA256とファイルのSHA256に `@noble/hashes` を使用する。乱数はブラウザの `crypto.getRandomValues` を使い、自作暗号は使わない。JavaScriptで厳密な定時間動作は保証できない。

HTTPではクリップボード読取ボタンが使えない場合がある。Ctrl+V、ファイル選択、ドロップを使用する。タッチ操作と端末固有の制限は別途実機確認が必要。

- [noble-hashes公式・APIと監査／定時間動作の制約](https://github.com/paulmillr/noble-hashes#readme)
- [Node.js HTTP server.close](https://nodejs.org/api/http.html#serverclosecallback)：待受を閉じる一方、既存接続の終了を待つ。切替ではcloseのコールバックを待たず同じポートでlistenし、upgrade済みのローカルWebSocketを維持する。
- [Node.js net実装](https://github.com/nodejs/node/blob/main/lib/net.js)
- [MDN Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts)

自動検証では、実ソケットの待受切替は注入したループバックに限定する。失敗系は疑似リスナーで検証し、検証のために実際のLAN待受を開かない。非セキュアAPI不在のブラウザ検証は実際のタブレット実機試験の代替ではない。
