# 複数の机との接続と識別

## 合意した責任範囲

- MCPは複数のペアリング済み接続先を扱う。製品上の接続数上限は置かず、認証途中・要求サイズ・待ち時間等の技術的制限は維持する。
- 個別の机に作用する全ツールは、1机でも `deskId` 必須。カレント机や省略時の推測は設けない。
- 机IDはペアリング済みの接続先の識別子。永続IDの維持を保証する仕組みは作り込まない。
- 名前・タイトル色・壁紙と、会話上の「元の机」「新しい机」をどう対応させるかはAIが判断する。判別できないときに確認する・実行しないこともAI向けの心得で、アプリが意味を判定して強制しない。
- 同名ファイルの複数オープン、上書き保存、利用者によるLOADは従来の扱い。追加の禁止・履歴保護・自動バックアップを設けない。必要なバックアップや注意喚起は共同作業中の判断に任せる。
- AIごとの振る舞いを均一化しない。複数机と会話を扱える十分な能力のAIを推奨するに留める。
- ベルは机ID付きの実験的な待機。複数机で待つかはAIが決める。まとめ待機・常駐・自動処理は追加せず、将来pushに置換する余地を残す。

## ツールの境界

机ID必須：参照、編集、選択・指差し、カメラ、見た目、Undo/Redo、画像取得・取込・ラスタ化、SAVE/LOAD、メッセージ、ベル、共有開始・終了、ペアリング情報取得、接続解放。

サーバー全体：`desk_connections`、`desk_connection_info`、新規受付を開く `desk_pairing_open`、秘密recordを渡す `desk_pairing_restore`、ブラウザ起動、ポート・LAN設定、Help、素材・ハンコのカタログ。

`desk_connections` は机ID・接続状態・机名・背景（タイトル色・壁紙・無地色）を返す。切断済み登録も区別し、名前でルーティングしない。秘密情報は含めない。

## 実装方針

接続ごとにWebSocket・処理待ち・ペアリング・ベル・保存処理中状態・共有サーバーを保持。ツールはIDから対象を解決し、複数ステップの要求も最初のソケットへ固定する。切断・再接続後の別ソケットへ途中の処理を自動再送しない。無効ID・切断・不明な応答は別机へ振り替えない。

表示IDはペアリングUUIDから短い公開識別子を導出し、認証後にブラウザの表示へ反映する。認証は引き続き秘密recordとnonce/proofで行い、公開IDを認証資格にしない。接続内のID衝突は検出して登録を拒否する。

`desk_pairing_open` は追加受付で、既存ペアリングを消さない。復帰も対象recordだけに作用する。ポートとLAN設定はプロセス全体のまま扱う。

MCP経由の新規作成時は、接続中の机名を元に「無題」「無題(2)」等を候補にする。LOADした名前は変更しない。AIは必要に応じて命名・配色を提案できる。

## 確認項目

机ID省略拒否、同じ部品IDのある二机の交互・並行編集、応答の所属、対象切断と未完了操作、他机を保った解放・復帰、個別の保存・ベル・メッセージ・共有、新規命名、全既存テストの呼び出し移行。更新時は旧机を保存し、ブラウザ・MCPを揃えて更新する。公開APIの破壊的変更として扱う。

## 検証結果（2026-10-24）

- `npm test`：233件成功。接続を固定した複数ステップ要求、再接続後の旧要求の拒否、遅れたclose、別机を保った復帰登録を含む。
- `npx tsc --noEmit`／`npm run build`：成功。ビルドの従来の大きなチャンク警告は残る。
- 関連E2E 14件成功：multiple-desks、connection-investigation、connection-url、desk-release、desk-identity、handoff、port-change、activity-led、bell-wait、share-browser、desk-file-tools。
- 二机に同じ部品IDを配置し、並行編集・個別SAVE/LOAD・二つの共有URL・メッセージ・片方の解放と共有停止を検証。無効／省略IDを拒否し、他机へ振り替えない。一覧取得でベルLEDを消さない。
- ブラウザ全体114件も実行。新仕様の期待値を修正して関連試験を再実行した。以下の既存9件の非成功（8失敗＋1タイムアウト取消）は、変更前HEADを `/tmp` へ書き出してビルドした環境でも同じように再現したため、今回の修正には含めない。

既存の非成功：browser（旧図形ボタン操作）、desk-pdf（メニュー項目数）、eight-anchors（表示アンカー誤差）、focusのフロート配置試験（ボタン数）、link-card（キーボードでのpopup待ち）、markdown-preview（ベル用プレビューとセレクター重複）、media-card（既定寸法）、reaction-picker（旧文字キャプション）、toolbar-captions（旧ボタン構成）。全E2Eが成功したという扱いにはしていない。

MCP・ブラウザを新版へ更新し、黒と赤の二机の同時接続・AIによるコピーを利用者が確認済み。旧ブラウザの表示IDは新APIの接続IDと一致しないため、旧タブをそのまま新版サーバーの操作確認に使わない。保存形式は変更しない。
