# 線のマウス接続：調査結果

2026-10-30。再現できた問題の修正まで実施。利用者の元の現象は原因を断定せず、経過観察とする。

## 紹介机で確認したこと

Y字の3端点は座標が一致していたが、接合点IDは付いていなかった。AIで同じIDを指定すると分岐表示が動いた。
revision331〜352の操作履歴には、両端が同じ量だけ動く線全体の移動と、片側だけを動かす操作が混在している。たとえばrevision333は両端が(+20,+68)、338は両端が(0,-24)移動し、元の接着が外れた。最終的にどの操作・入力方法で未接続にしたかは履歴だけでは確定できない。

## 確認・再現できた仕様と問題

1. **線全体の移動は新しい接合を作らない。** 端点の座標が揃っても接合点IDは付かない。既存の線同士の接合は維持し、対象への接着は外す。偶然の重なりを接続しないため、この区別は維持する案が妥当。
2. **3本目の端点ドラッグは通常動作する。** 隔離したブラウザの200%表示で、既存の2本の接合点へ3本目をドラッグすると接続できた。角丸め48・丸め0とも同じ結果。角丸めは論理端点を変更しない。
3. **すでに重なった端点を動かして元へ戻すと接続されない。** 同じブラウザ操作で再現。候補は緑になるが、離した時の差分がゼロなので `gestureOperations` 冒頭が空操作を返す。クリックで接着を外さないための早期returnが、接続したい場合にも作用する。
4. **拡大時は、グリッドで揃っただけの状態も作れる。** 計算処理で確認。24単位グリッド、200%表示、接続先(288,192)、操作点(298,202)では、画面上の距離約28.3pxが端点吸着18pxを超える。その後グリッド処理で(288,192)へ丸めるため、同じ座標でも接合しない。グリッドが接続判定より優先なのではなく、接続候補なしの場合の後段処理。

## 表示と確定処理

`diagram-drawing.ts` の `drawSnapTargets` と `diagram-gestures.ts` の接続確定は別々に候補を求める。確定側は自分の接合グループ除外、図形との距離優先・同距離では図形優先、同じ線の両端を一群にできない制限を持つ。表示側はそれらをすべて共有していない。候補が緑でも実際には接合されないケースがある。

## 対応

- 線全体の移動と端点ドラッグの役割は維持する。
- 実装済み：画面上で2pxを超えて端点をドラッグした場合、最終差分がゼロでも接続を判定する。単なるクリックでは机を変更しない。
- 実装済み：端点候補表示と確定処理を `endpointSnap` に共通化。ドラッグ開始時の候補シーンを使い、実際に成立する候補だけを強調する。
- グリッドで同じ座標になった場合の再判定は別途相談する。拡大時の操作性は改善できるが、吸着範囲を事実上広げることになる。

利用者から「線全体を動かしていたかもしれない」との補足あり。今回の事象を一つの原因へ断定せず、上記の再現事項を分けて扱う。

## 検証

接合・図形・グリッド・ロックの関連単体テストを通過。実ブラウザでクリックのみの無変更、端点を離して戻した時の接合、通常接合、接合点移動、Alt解除、UNDO、保存・読込を確認。候補の図形優先、自己接合グループ除外、同じ線の両端を一群にしない判定も単体テストで確認。
