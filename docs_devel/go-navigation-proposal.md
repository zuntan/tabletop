# GO：経路をたどる視点移動

2026-10-27／利用者からの実装相談・依頼。**構想段階。方針確認前に実装しない。**

## 目的

広い机の線やピンの糸をたどり、離れた2点の位置関係を移動の過程から理解する。拡大すると接続先が見えず、縮小すると文字が読めない関係図などを想定する。

単に到着先へ最短距離で中央寄せする機能ではない。3Dプリンタのヘッドのように経路を正確に走り、チョロQのように気持ちよく加減速する。「みゅーーーーん」と動き、何度も押したくなる楽しさも目的。

## 基本移動

1. 出発地点のGOを画面中央へ移動する。
2. 中央寄せ完了後、経路を走り始める。
3. 直線・折れ線・フリー連続線の形状に沿って視点を移動する。曲がり角も経路どおりに進む。
4. 到着先がカードなら、そのカードを画面中央へ配置して停止する。

原則ズーム倍率は維持する。出発前の中央寄せは、画面端からの発進で経路がすぐ見えなくなるのを防ぐため。

経路上を走る小さなマーカーとカメラ追従も検討するが、外観・追従方法は動作を見て調整してよい。

### 速度と演出

- 発進で加速、走行中は滑らかに進み、必要なら曲がり角で減速する。
- 到着時は減速して停止する。
- 距離に応じた所要時間と上限を設け、長距離で待たせすぎない。
- 速度・時間・加減速曲線・マーカーは未決定。実際のアニメーションで調整する。

## GOオブジェクト

線の端点装飾ではなく、独立した机上オブジェクトを基本案とする。

- テレビ番組の「へぇーボタン」のような小さな卓上プッシュボタン。押すと少し沈む演出も候補。
- 上下左右4点アンカーを基本案とする。既存ピンの実装との違いは調査する。
- GO自身をカード等にアンカーでき、GOへ複数の線を接続できる。
- 同じアンカーへ複数本の接続を許す。各アンカーの用途は固定しない。
- 例：カード右側へGOを置き、左側をカードへの接続、右側を経路へ使う。ただし推奨にとどめる。
- カードに重なって押しにくければ利用者が配置を直す。
- 表示サイズは机のズームへ追従するのが基本。縮小率の緩和は検討可能だが、5%でも必ず押せることは要求しない。

### 線・矢印

線と矢印は同様の経路として扱い、**矢印の向きと進行方向は無関係**。矢印は関係の向き、GOは視点移動の指示である。

経路途中の別GOを理由に停止しない。GOは発射位置であり停車地点ではない。

## 経路・分岐

基本は2点間移動。連続線・フリー連続線の途中頂点は通過し、次の進路が一意ならそのまま続行する。

- 進路が複数で一意に決まらない場合は分岐で停止。
- 単なる線の交差と、実際の接続を区別する。
- 出発GOに複数の線がある場合も進路選択が必要。

### 分岐カンバン（将来段階）

分岐で一時停止し、分岐点を指す小さな吹き出しを表示する。

- 中に分岐部分の拡大マップと、各進行方向の選択ボタンを置く。
- 方向を選ぶと、その経路へ再発進する。
- 右下などに停止ボタン。背景は暗くしない。
- 吹き出しは机のズームに依存しない固定表示サイズでよい。
- マップは机画像の拡大でなく、経路の再描画でもよい。
- 4又以上も理想とするが、近すぎる角度は利用者の配置調整を許容する。
- 出発GOの複数経路選択にも同じUIを用いる。

## ピン・糸

ピン同士の糸をたどる移動も対象候補。

- ピン自体から起動するか、ピンへGOを接続するかは未決定。
- 通常の選択・移動と競合させない。この機能のためだけにコンテキストメニューを新設しない。
- 線と糸の先行順は既存構造を調べて相談する。
- 線・糸の経路取得と視点移動アニメーションを分離し、移動部分を共通利用する。過剰な汎用化はしない。

## 段階実装

1. **基本移動**：起動、出発中央寄せ、2点間移動、直線・折れ線・フリー連続線への追従、到着中央寄せ、加減速。「みゅーーーーん」の感触を先に試す。線／糸の先行順は相談。
2. **分岐停止**：接続追跡、分岐検出・停止、出発時に複数進路がある場合の扱い。選択UIはまだなくてよい。
3. **分岐カンバン**：吹き出し型拡大マップ、方向選択、再発進、停止。出発地点にも共通利用。

## 着手前の調査・相談

既存の線・連続線・フリー連続線・ピン・糸・アンカー・カメラ処理を確認し、以下を提案する。

1. 独立GOオブジェクトと現在の構造の整合性。
2. 線／ピン・糸のどちらを先行すると変更範囲を抑えられるか。
3. 経路追跡・視点アニメーションの共通化範囲。
4. 分岐判定に関する既存データ構造の制約。
5. 段階実装の具体的な切り分け。

未確定部分を独断で複雑化しない。見た目・時間・加減速・マーカーは実機で相談する。**まず調査と方針提案、その確認後に実装する。**
